## MISSION STATEMENT

This translation does not replace the Hebrew. It is a disciplined attempt to show, in English, Brazilian Portuguese, and German, what the Hebrew says, what it may mean, and where it remains open. Where ambiguity exists, it will be preserved or signaled. Where additions are necessary, they will be marked. Where choices are uncertain, notes will say so.

**This is not the closest translation to the original—it is the least dishonest version we could build.**

---

## PRIME DIRECTIVE (Non-Negotiable)

1. **Do not simplify what the Hebrew keeps complex.**  
2. **Do not clarify what the Hebrew leaves ambiguous.**  
3. **Do not add what the Hebrew does not say** (unless target grammar absolutely requires it).  
4. **When addition is unavoidable, signal it clearly.**

**If any rule conflicts with this principle, the principle wins.**

---

## OUTPUT STRUCTURE: THREE-TIER SYSTEM

Every translated passage organized in three layers:

### **Tier 1: Main Translation**
- Primary reading text
- Readable but visibly faithful to Hebrew
- **KEEP MAIN TEXT CLEAN:**
  - No inline commentary
  - No parenthetical mini-glosses
  - No explanatory prose in the line
  - **Limited ambiguity slashes ARE permitted** for a very small set of governed high-stakes terms (e.g., wind/spirit, side/rib, desire/turning, bruise/strike). These are governed by the locked glossary and Rule 2; they are not ad-hoc.
- Minimal smoothing
- This is what most readers see

### **Tier 2: Essential Notes**
- Maximum 3-5 notes per verse (default)
- Each note 1-2 sentences maximum (default)
- **Pivotal-verse exception:** Verses with extraordinary textual density (multiple ambiguities, contested readings, or structural significance) may carry 5-7 notes — but ONLY if: (a) the verse is logged as "pivotal" in the editorial log, (b) each note remains essential (not commentary), and (c) anything beyond core clarification moves to the companion file. This is a governed exception, not a loophole.
- **ENHANCED VISIBILITY THROUGH DESIGN:**
  - Use boxed/highlighted format
  - Color-coded icons (🔴 Critical, 🟢 Lexical, 🔵 Grammatical, 🟡 Theological)
  - Placed immediately after verse (not at chapter end)
  - Bold Hebrew terms
  - Clear visual hierarchy
- Only for features that would otherwise disappear:
  - Ambiguity
  - Unusual grammar
  - Wordplay
  - Transliterated terms
  - Culturally loaded concepts
  - Uncertainty levels

### **Tier 3: Appendix/Study Layer** *(Optional - not required per verse)*
- Hebrew text + transliteration
- Literal word-for-word gloss
- Full linguistic analysis
- Pattern tracking across verses
- **Use:** Reserve for verses with significant ambiguity, textual issues, or end-of-chapter comprehensive analysis

## THE 24 RULES

### **I. SEMANTIC RULES (Meaning & Words)**

#### **Rule 1: Controlled Lexical Consistency**
Same Hebrew word → Same base translation **by default**

**Policy:**
- Follow locked glossary above
- Contextual shifts allowed when **clearly required by immediate context**
- **All shifts must be justified** in editorial log
- **Public notes** explain shifts only when reader needs to know

**Why:** Consistency reveals patterns; controlled flexibility prevents rigidity. **Uncontrolled lexical drift is the main risk vector in this system.**

**Example:**
```
ארץ (eretz)
- Default: "land/terra/Land"
- Contextual: "ground/solo/Boden" (when clearly soil/surface)
- Never: Random alternation between "earth," "world," "region," "Welt," "Erde"
- Justification: Document in editorial log
```

---

#### **Rule 2: Preserve Ambiguity**
If Hebrew supports 2+ meanings and context doesn't force one choice, preserve both

**Decision Tree:**
```
Hebrew word has multiple meanings?
├─ NO → Use single best translation
└─ YES ↓
    Context clearly resolves?
    ├─ YES → Use resolved meaning
    └─ NO ↓
        Both meanings matter to text?
        ├─ NO → Use primary meaning + note alternative
        └─ YES ↓
            Can limit to 2 options in main text?
            ├─ YES → Use slash: wind/spirit, vento/espírito, Wind/Geist
            └─ NO → Choose 2 most important, note rest
```

**Slash Policy:**
- Maximum 2 options in main text
- Third option → footnote
- Example: wind/spirit (main) + breath (note); Wind/Geist (main) + Atem (note)

---

#### **Rule 3: Avoid Imported Theology**
Don't sneak in later religious concepts not justified by immediate Hebrew context

**High-Risk Theological Overlays:**

| Avoid | Why | Use Instead |
|-------|-----|-------------|
| Heaven(s) / Céu (spiritual) / Himmel (spiritual) | Post-biblical spiritualization | sky/skies / céu/céus / Himmel (physical) |
| Spirit (capital S alone) / Espírito / Geist (capitalized alone in German) | Trinitarian overlay | wind/spirit / vento/espírito / Wind/Geist |
| The Earth / A Terra / die Erde (planet concept) | Modern planetary concept | the land / a terra / das Land |
| Firmament / Firmamento / Firmament | Medieval cosmology | raqia (+ explanation) |

**Test:** Would an ancient Hebrew reader hear this theological meaning?  
If NO → don't import it

**Corollary — Restraint matters both ways:**
The same discipline that forbids importing later theology also forbids importing anti-traditional reaction as if unfamiliarity equals originality. Choosing the less-familiar reading simply *because* it is less familiar is as dishonest as smoothing. Ambiguity means ambiguity — not reflexive novelty. If the traditional reading is one legitimate option among several, it must remain visible alongside the others, not be silently excluded.

**German Note:** German capitalizes all nouns grammatically (see Rule 20 exception), but avoid theological overlay through word choice itself.

---

#### **Rule 4: Transliterate Strategic Terms**
Keep Hebrew when translation imports false connotations

**When to Transliterate:**
1. No accurate target-language equivalent exists
2. Common translation carries misleading baggage
3. Term is structurally/cosmologically critical

**Current Terms:**

**רָקִיעַ (raqia):**
- **Keep "raqia" in main text throughout Genesis 1 (Transparent Edition) - ALL LANGUAGES**
- First occurrence: "raqia (expanse)" / "raqia (expansão)" / "raqia (Ausdehnung/Gewölbe)"
- Define in note: "From root meaning 'to hammer/beat'; describes sky/expanse; verse 8 identifies as 'sky'"
- **Subsequent uses in Transparent Edition:** Keep "raqia"
- **Reader Edition:** May use "expanse/expansão/Ausdehnung" but must preserve "raqia" in notes
- **Why strict:** Prevents uncontrolled lexical drift—the main risk vector

**תֹהוּ וָבֹהוּ (tohu vavohu):**
- Optional transliteration when preserving uncertainty
- Use minimal imagistic language: "chaos and void / caos e vazio / Chaos und Leere"
- Note: "Rare phrase (3x in Bible); meaning debated; associated with destruction/desolation"

**Format:** *Italicize* + define in footnote once

### **II. STRUCTURAL RULES (Grammar & Form)**

#### **Rule 5: Respect Hebrew Grammar**
Preserve grammatical features when readable; adjust minimally when not

**What to Keep:**
- Repetition patterns
- Unusual constructions
- Missing pronouns (don't auto-add)
- Gender agreements (especially in Portuguese & German)
- "Between...and between..." patterns
- Fronting for emphasis

**What to Adjust:**
- Word order when incomprehensible
- Verb-subject position when archaic

**Balance Test:** Structure preserved + comprehensibility maintained

---

#### **Rule 6: Preserve Poetic Doubling & Repetition**
Hebrew doubles roots and pairs synonyms for artistic effect—keep it

**Root Doubling:**
```
Hebrew: מַזְרִיעַ זֶרַע (mazria zera)
✓ EN: seeding seed
✓ PT: semeando semente
✓ DE: samend Samen / Samen-säend
✗ EN: seed-bearing (collapses doubling)
✗ DE: samentragende (collapses into single adjective)

Hebrew: עֹשֶׂה פְרִי (oseh pri)
✓ EN: making fruit
✓ PT: fazendo fruto
✓ DE: Frucht-machend
✗ EN: fruit-bearing (collapses)
✗ DE: fruchttragende (collapses)
```

**Synonym Pairing:**
```
Hebrew: דֶּשֶׁא עֵשֶׂב (deshe esev)
✓ EN: grass, herbs
✓ PT: relva, ervas
✓ DE: Gras, Kraut
✗ EN: vegetation (collapses pair into abstraction)
✗ DE: Bewuchs (collapses pair)
```

**German Compound Policy:**
German compound capability can preserve Hebrew poetic doubling and construct chains:
- Compounds acceptable when preserving Hebrew structure
- "samend Samen" or "Samen-säend" preserves doubling (even if odd)
- "Meeresbewohner" (sea-dwellers) acceptable for construct chains
- Avoid over-compounding that creates false precision
- Don't invent elaborate German compounds not justified by Hebrew

**Note:** Yes, it sounds odd. That's intentional Hebrew poetic style.

---

#### **Rule 7: Preserve Parallel Structure**
Lock formula **pattern**, not necessarily identical wording in all cases

**Genesis 1 Locked Formula Patterns:**

**English:**
- "And God said..."
- "And it was so"
- "And God saw that good" / "And God saw that it was good"
- "And was evening, and was morning, [X] day"

**Portuguese:**
- "E Deus disse..."
- "E foi assim"
- "E Deus viu que bom" / "E Deus viu que era bom"
- "E foi tarde, e foi manhã, dia [X]"

**German:**
- **Reader Edition:** "Und Gott sagte..." (elevated contemporary; aligns with Rule 10 default)
- **Transparent Edition:** "Und Gott sprach..." (slightly more elevated; preserves narrative weight closer to Hebrew register without crossing into Luther archaism)
- Choice is edition-bound, not translator-discretionary; document in editorial log if deviated
- "Und es war so"
- "Und Gott sah, dass gut" / "Und Gott sah, dass es gut war"
- "Und es war Abend, und es war Morgen, [X] Tag"

**Policy for "that good" vs "that it was good":**

Where Hebrew compression can be carried intelligibly in target language, preserve it. Where target-language grammar requires expansion, use minimal addition and mark it consistently.

**CRITICAL SAFEGUARD:**
Each edition must choose and declare one default policy:
- **Transparent Edition:** "that good / que bom / dass gut" (preserves compression)
- **Reader Edition:** "that it was good / que era bom / dass es gut war" (minimal addition marked)

**Apply chosen policy consistently throughout the edition.**

**Keep formulas stable across repeated occurrences unless meaningful Hebrew variation requires a documented change.**

### **III. VERB RULES (Action & Tense)**

#### **Rule 8: Reflect Verb Nuance**
Hebrew verbs ≠ English/Portuguese/German tenses; preserve meaningful distinctions

**Future-as-Command (Jussive):**
```
Hebrew: יְהִי (yehi) - future form used as command

English Options (pick one consistently per edition):
✓ "Shall be light" (closer to Hebrew form)
✓ "Let there be light" (traditional, acceptable)
Note once: "Hebrew uses jussive/future for divine command"

Portuguese:
✓ "Haja luz" (subjunctive - excellent match)
✓ "Seja luz" (alternative)
Note: "Hebraico usa jussivo para comando divino"

German:
✓ "Es werde Licht" (Konjunktiv I - preserves jussive, slightly archaic feel)
✓ "Es soll Licht sein" (modern construction)
✓ "Licht soll sein" (alternative modern)
Note: "Hebräisch verwendet Jussiv für göttlichen Befehl"

GERMAN TRANSPARENT EDITION CHOICE:
- Konjunktiv I when readable ("Es werde Licht")
- Note at first occurrence that this preserves Hebrew jussive form
- Acceptable slight archaic resonance in service of linguistic transparency

GERMAN READER EDITION CHOICE:
- Modern construction if Konjunktiv I feels too archaic for general readers
- "Es soll Licht sein" or similar
```

**Voice Preservation:**
```
Passive Hebrew verbs → Passive translation in ALL languages
Hebrew: וְתֵרָאֶה (vetei'ra'eh) - passive "be seen"
✓ EN: "and the dry ground shall be seen"
✓ PT: "e a terra seca será vista"
✓ DE: "und das trockene Land werde gesehen" (passive with werden)
✗ EN: "and dry ground appear" (active - wrong voice)
✗ DE: "und trockenes Land erscheine" (could be ambiguous)

German has robust passive voice system with werden + past participle - exploit this strength
```

**Participles (Ongoing Action):**
```
Hebrew: מְרַחֶפֶת (merachefet) - present participle
✓ EN: hovering (present progressive)
✓ PT: pairando (gerúndio)
✓ DE: schwebend (Partizip Präsens)
✗ EN: hovered (simple past - wrong aspect)
✗ DE: schwebte (simple past - wrong aspect)

German Participle System:
- Present: schwebend (hovering), trennend (separating), schaffend (creating)
- German has excellent participle system - use it to preserve Hebrew aspect
- "pairando" in Portuguese and "schwebend" in German both capture ongoing action better than English "hovering"
```

---

#### **Rule 9: Handle Converting VAV**
The vav-consecutive (ו) changes future→past in narrative

**Main Text Policy:**
- Translate into natural past tense in all languages
- Don't force awkward constructions

**Note Policy:**
- Explain at **first important occurrence**
- Brief format: "Converting-vav changes future יְהִי to past"
- "Vav conversivo muda futuro para passado"
- "Vav conversivum wandelt Futur in Vergangenheit"
- Don't repeat explanation every verse

### **IV. TONE & TRANSPARENCY RULES**

#### **Rule 10: Neutral Formal Register**
Slightly elevated, clear, serious—avoid both extremes

**Target Register:**
- Formal enough for serious literature
- Clear enough for modern readers
- Not archaic, not casual

**English:**
```
✗ "And God spake" (archaic)
✓ "And God said" (neutral formal)
✗ "Then God was like" (too casual)
```

**Portuguese:**
```
✗ "E disse o Senhor Deus" (overly biblical when not in Hebrew)
✓ "E Deus disse" (elevated but natural)
✗ "Aí Deus falou" (too colloquial)
```

**German:**
```
✓ "Und Gott sagte" (elevated neutral - RECOMMENDED)
✓ "Und Gott sprach" (alternative, slightly more elevated)
✗ Archaic verb forms (unnecessarily distant from modern readers)
✗ "Dann sagte Gott" (too casual)
✗ "Da sprach Gott" (too Luther-esque if used rigidly)

GERMAN POLICY: Elevated but contemporary German
- NOT Luther Bible archaisms as default
- NOT casual modern slang
- Formal but accessible
- No archaic pronouns for divine address (no "du" vs. "Sie" distinction for God)
- Standard educated German of 2020s
```

#### **Rule 11: Signal All Additions**
Mark words not in Hebrew; distinguish types of additions

**Three-Part System:**

**A. Italics:** For minimal grammatical additions in main text
```
Hebrew: וַיַּרְא אֱלֹהִים כִּי טוֹב
Literal: "And-saw God that good"

✓ EN: "And God saw that *it was* good"
     (*it was* added for English grammar)
     
✓ PT: "E Deus viu que bom"
     (no addition needed in Portuguese - compression natural)
     
✓ DE: "Und Gott sah, dass *es* gut *war*"
     (*es* and *war* added for German grammar)
```

**B. Brackets:** For rare clarifications in main text (use sparingly)
```
Only when absolutely unavoidable for comprehension
Keep main text clean
```

**C. Notes/Gloss:** For untranslatable particles
```
Hebrew: אֶת (et)
✗ Main text: "God created [את - direct object marker] the sky"
✓ Note: "Hebrew includes את (et), untranslatable direct object marker"
✓ Gloss: "created [et] the-sky"
```

**Policy:** Don't clutter main translation with grammar labels—that's what notes and gloss are for

**German Note:** German requires more grammatical additions than Portuguese but fewer than English. Track all additions consistently.

---

#### **Rule 12: Avoid False Precision**
Don't invent details Hebrew leaves vague

**Examples:**
```
✗ "cosmic ocean abyss layer" (sci-fi cosmology)
✓ "the deep / o abismo / die Tiefe" (honest to Hebrew)

✗ "hammered metallic dome structure / gehämmerte metallische Kuppelstruktur"
✓ "raqia (expanse/sky)" + note on meaning
```

**Test:** Is this detail **in the Hebrew** or **in my interpretation**?

**German Warning:** German compound words can easily create false precision. "Himmelsgewölbe" (sky-vault) sounds more specific than Hebrew רָקִיעַ justifies.

---

#### **Rule 13: Uncertainty Levels**
Every note about difficult terms should indicate confidence level

**Three Levels:**

| Level | Definition | When to Use |
|-------|-----------|-------------|
| **Probable / Provável / Wahrscheinlich** | Strong evidence, wide scholarly agreement | Standard translations |
| **Possible / Possível / Möglich** | Reasonable option, debated among scholars | Alternative views |
| **Uncertain / Incerto / Ungewiss** | Genuinely unclear, multiple valid theories | Rare/unique words |

**Examples:**
```
תְהוֹם (tehom):
- Probable: "the deep / o abismo / die Tiefe"
- Possible: "deep waters / águas profundas / tiefe Wasser," "abyss / abismo / Abgrund"
- Uncertain: "cosmic ocean" (speculation)

תֹהוּ וָבֹהוּ (tohu vavohu):
- Possible: "chaos and void / caos e vazio / Chaos und Leere"
- Uncertain: exact meaning (appears only 3x in Bible)
```

**Prevents false confidence in notes across all languages.**

### **V. ADVANCED COORDINATION RULES**

#### **Rule 14: Annotate Wordplay**
Mark Hebrew puns, paronomasia, and sound-play

**When Translatable:**
- Preserve in main text if possible
- Note the wordplay

**When Untranslatable:**
- Translate meaning literally
- Note: "Hebrew wordplay on X and Y cannot be rendered / Jogo de palavras hebraico não pode ser reproduzido / Hebräisches Wortspiel kann nicht wiedergegeben werden"

**Cross-Reference Policy (added v2.4.2):**

Cross-references are permitted when they reveal real textual connections. Without a cap, they proliferate into commentary.

**Two categories:**
- **Lexical / formulaic cross-references** (same Hebrew word, formula, or direct narrative echo reused): **uncapped**, but each must be documented in the editorial log. Example: *tselem/demut* at Gen 1:26–27 → Gen 5:1–3 (same word-pair, inverted) = legitimate.
- **Interpretive cross-references** (thematic similarity without lexical link): **capped at 0–2 per verse** in Tier 2. Must be logged. Example: "this echoes the Exodus theme" without shared vocabulary = interpretive, cap applies.

**Test:** Is the connection visible in the Hebrew text itself (shared root, repeated formula, explicit narrative callback)? If yes → lexical, uncapped. If the connection requires theological reasoning to perceive → interpretive, capped.

#### **Rule 15: Three-Output Rule**
Each verse should ideally produce three forms (reduces pressure on single line)

**A. Main Translation** (Tier 1)
- Readable, disciplined
- What most readers see

**B. Literal Gloss** (Tier 3 - optional)
- Word-for-word (even if rough)
- Shows Hebrew structure

**C. Essential Notes** (Tier 2)
- Explains difficult choices
- 1-2 sentences each
- Uncertainty levels marked

**Why:** Stops forcing one line to do three incompatible jobs

#### **Rule 16: Cross-Language Alignment**
Multilingual project requires consistency verification across all target languages

**After drafting each verse in all languages, verify:**

**Trilingual Alignment Checklist (EN ↔ PT ↔ DE):**
- [ ] Same lexical choices from glossary?
- [ ] Same ambiguity policy (slash placement)?
- [ ] Same formula structure?
- [ ] Same interpretive restraint?
- [ ] Same additions marked?
- [ ] German gender mismatches documented?

**Gender Awareness:**
- Portuguese & German preserve grammatical gender; English doesn't
- When gender could be misread theologically, note: "Grammatical gender, not ontological / Gênero gramatical, não ontológico / Grammatisches Geschlecht, nicht ontologisch"
- **German-specific:** Track all cases where German grammatical gender differs from Hebrew:
  - רוּחַ (fem.) → Wind/Geist (masc.) - NOTE when theologically relevant
  - תְהוֹם (fem.) → die Tiefe (fem.) - matches Hebrew, no issue
  - Document all mismatches in editorial log

**DIVERGENCE POLICY:**
When one language must diverge from others due to grammatical requirements:
- Document reason in editorial log
- Ensure divergence is grammatical, not interpretive
- Verify other two languages remain aligned where possible
- German compound usage may diverge for structural reasons - justify in log

**If any language drifts into paraphrase, pull it back.**

#### **Rule 17: Definite Article Consistency**
Translate Hebrew definite article ה (ha-) consistently

**Basic Rule:**
- Hebrew has article → target language has article
- Hebrew lacks article → don't add (unless target idiom requires)

**Exception: Proper Names**
- ה (ha-) may mark term becoming proper name
- Example: הָאָדָם (ha'adam) = "the human / o humano / der Mensch" → "Adam / Adão / Adam" (when becomes name)
- **Policy:** Flag the shift in a note

**Absence Matters:**
When Hebrew **lacks** article where expected, preserve or note the absence if meaningful

**GERMAN ARTICLE SYSTEM EXTENSION:**

German has sophisticated article system with grammatical gender + 4 cases:
- **Nominative:** der/die/das (masculine/feminine/neuter)
- **Accusative:** den/die/das
- **Dative:** dem/der/dem
- **Genitive:** des/der/des

**German Article Policy:**
- Hebrew ה → German definite article (der/die/das in appropriate case)
- Hebrew lacks article → German uses:
  - No article when grammatically natural
  - ein/eine (indefinite) when target grammar requires

**Grammatical Gender Assignment (German):**
- Follow German natural gender where available (das Licht, die Finsternis, der Himmel)
- When Hebrew gender conflicts with German grammar, NOTE the mismatch in Tier 2
- Track all gender mismatches in editorial log:
  - רוּחַ (fem. Hebrew) → der Wind/der Geist (masc. German) - DOCUMENT
  - מַיִם (masc. plural Hebrew) → das Wasser (neut. singular German) - DOCUMENT
  - אֶרֶץ (fem. Hebrew) → das Land (neut. German) - DOCUMENT when relevant

**Example Note for Gender Mismatch:**
"Hebrew רוּחַ is grammatically feminine; German Wind/Geist is masculine. This is grammatical gender, not ontological attribute."

#### **Rule 18: Numbers & Ordinals**
Preserve cardinal vs. ordinal distinction

**Critical Distinction:**
```
Hebrew: יוֹם אֶחָד (yom echad) - DAY ONE
✓ EN: "one day" (cardinal number)
✓ PT: "um dia" (cardinal)
✓ DE: "Tag eins" (cardinal) — **RESOLVED 2026-04-18.**
   "Ein Tag" reads as indefinite "a day"; "Tag eins" renders
   the cardinal label cleanly. Decision logged.
✗ EN: "the first day" (ordinal - not in Hebrew)
✗ DE: "der erste Tag" (ordinal - not in Hebrew)

Hebrew: יוֹם שֵׁנִי (yom sheni) - DAY SECOND
✓ EN: "second day" (ordinal)
✓ PT: "segundo dia" (ordinal)
✓ DE: "zweiter Tag" (ordinal, no article) / "der zweite Tag" (with article)
```

**Why it matters:** Day 1 is treated differently linguistically—this is significant

**German Note:** German ordinals can take articles or not; follow Hebrew article pattern.

#### **Rule 19: Priority Order When Rules Conflict**
Real translation has edge cases where rules conflict—here's the hierarchy

**When Rules Conflict, Follow This Order:**

1. **Preserve meaning** (most important)
2. **Preserve ambiguity** (when Hebrew is ambiguous)
3. **Preserve structural pattern** (formulas, repetition)
4. **Preserve lexical consistency** (glossary)
5. **Preserve readability** (don't break language)

**This prevents paralysis when facing difficult choices.**

#### **Rule 20: Capitalization**
Don't capitalize interpretive terms beyond what Hebrew justifies

**Standard Policy (English & Portuguese):**
- **Lowercase** for common nouns (even theologically significant ones)
- **Capitalize** only proper names and sentence beginnings
- Don't use capitalization to import theology

**Examples:**
```
✓ "spirit of God / espírito de Deus" (descriptive)
✗ "Spirit of God / Espírito de Deus" (implies Trinity)

✓ "sky / céu" or "skies / céus"
✗ "Heaven / Céu" (theological realm)

✓ "the land / a terra"
✗ "the Earth / a Terra" (when treating as planet name)
```

**GERMAN EXCEPTION TO RULE 20:**

German capitalizes **ALL nouns** grammatically (Substantive), not for theological emphasis:
- **Himmel** (sky), **Geist** (spirit), **Erde** (land), **Licht** (light), **Finsternis** (darkness), **Gott** (God)
- This is standard German orthography (Rechtschreibung)

**German Capitalization Policy:**
- German's grammatical noun capitalization is **PERMITTED** as it's a language requirement, not theological import
- However:
  - **NO additional emphasis through GROSSBUCHSTABEN (all caps)**
  - **NO special fonts/formatting for theological terms**
  - **NO capitalization of adjectives or other parts of speech for emphasis**
  - The capitalization is **grammatical, not interpretive**
  
**In German notes, when necessary:** 
"Großschreibung folgt deutscher Grammatik, keine theologische Betonung / Capitalization follows German grammar, not theological emphasis"

**Example:**
```
German: "der Geist Gottes" - both nouns capitalized grammatically
English: "the spirit of God" - lowercase unless proper name
Portuguese: "o espírito de Deus" - lowercase unless proper name
```

#### **Rule 21: Don't Smuggle Commentary into Main Text**
Translation ≠ commentary in disguise

**Policy:**

**Main text must remain translation, not embedded commentary.**

**Examples of Smuggling:**

```
✓ "raqia" + Note: "From root 'to hammer' / Da raiz 'martelar' / Von der Wurzel 'hämmern'"

✗ "spontaneous vegetative generation / geração vegetativa espontânea / spontane vegetative Erzeugung"
✓ "the land brought out vegetation / a terra produziu vegetação / das Land brachte Vegetation hervor"
```

#### **Rule 22: Text-Critical Restraint**
Translate the established base text; note variants, don't silently adopt them

**Base Text Policy:**
The default base text for this project is the **Masoretic Text** as represented in **Biblia Hebraica Stuttgartensia (BHS)** or **Biblia Hebraica Quinta (BHQ)**.

**Policy on Variants:**
- Significant textual variants from:
  - Septuagint (LXX)
  - Samaritan Pentateuch
  - Dead Sea Scrolls
  - Alternate vocalization traditions
- May be **noted** in Tier 2 or Tier 3
- Must **not be silently adopted** in main text

**Why:** Anchors project to actual editorial practice; prevents silent text choices

**No-Harmonization Principle (added v2.4.2):**

Translation of a verse must be governed first by its **immediate Hebrew context** and **book-level patterning**, not by later canonical harmonization or doctrinal back-reading.

This means:
- Do not translate Gen 3:15 to match New Testament Christology.
- Do not translate Gen 1:2 *ruach* to match later pneumatology.
- Do not translate Gen 2:17 *beyom* to match Gen 5:5 death-timing.
- Each verse answers to its own text first. Cross-canonical resonance belongs in notes (Tier 2) or appendix (Tier 3), never in the main translation.

**Why:** Harmonization is the single most common way translations silently import post-biblical readings. This principle makes Rule 3 (Avoid Imported Theology) concrete at the verse level.

#### **Rule 23: Genre Sensitivity**
Patterns specific to Genesis 1 should not mechanically colonize later chapters

**Policy:**
- **Genesis 1:** Highly patterned, liturgical, locked formulas apply
- **Genesis 2+:** Narrative shifts; patterns and locked formulas specific to Genesis 1 should not be mechanically imposed
- **Throughout:** Repetition, rhythm, and lexical consistency remain important
- **Always:** Genre shifts must be respected

**Why:** Prevents Genesis 1 system from becoming rigid template for entire book

#### **Rule 24: Edition Identity**
Every published rendering must declare its edition type

**Two Edition Types:**

### **TRANSPARENT EDITION**
**Purpose:** Maximum linguistic visibility of Hebrew features

**Characteristics:**
- Prioritizes Hebrew structure and compression
- "that good / que bom / dass gut" (preserves Hebrew compression)
- Slight awkwardness acceptable when mirroring Hebrew
- Root doubling, repetition, unusual constructions maximally preserved
- "raqia" kept throughout (all languages)
- Minimal smoothing
- **German-specific:** May use Konjunktiv I for jussive ("Es werde Licht")

**Target Audience:** Serious students, scholars, those studying Hebrew patterns

---

### **READER EDITION**
**Purpose:** Accessible reading while maintaining honesty

**Characteristics:**
- Same locked glossary
- Same ambiguity preservation policy
- Same notes system
- Same avoidance of theological smoothing
- Slightly smoother syntax where target grammar requires
- "that it was good / que era bom / dass es gut war" (minimal addition marked)
- May use "expanse/expansão/Ausdehnung" for raqia (but preserve in notes)
- Readability priority within honest constraints
- **German-specific:** May use modern constructions if Konjunktiv I feels archaic

**Target Audience:** General readers seeking accurate but readable translation

**ANTI-DRIFT SAFEGUARD (added v2.4.2):**

Reader Edition may smooth:
- syntax and punctuation
- slightly awkward target-language scaffolding
- some compression where readability requires expansion (marked per Rule 11)

Reader Edition may **NOT** smooth away:
- ambiguity (Rule 2 slash notation stays or is noted)
- passive voice (where Hebrew is passive)
- cardinal vs. ordinal distinction (Rule 18)
- root doubling where essential to Hebrew pattern (Rule 6)
- discourse structure (speech boundaries, aposiopesis)
- theologically open wording (where Hebrew leaves options)

**This distinction is the most important anti-drift safeguard for the future of the project.** If Reader Edition silently loses these features, it becomes a normal modern Bible translation — which is exactly what TT was built to not be.

---

**BOTH EDITIONS SHARE:**
- Locked glossary (Rule 1)
- Ambiguity preservation (Rule 2)
- No theological smoothing (Rule 3)
- Same essential notes (Tier 2)
- Same base text (BHS/BHQ)
- Same uncertainty levels (Rule 13)
- Same quality control standards

**POLICY:**
Each edition must declare its type and apply its chosen policies **consistently throughout**.

**PRESENTATION LAYERS (ADDITIVE, added v2.4.1):**

A single edition MAY be presented in two layered views within **one chapter file**:

- **Continuous Reading** — verses flow as prose with superscript verse numbers (¹²³…); paragraph breaks at natural narrative joints (e.g., creation days in Genesis 1); no inline notes.
- **Verse-by-Verse Study** — the existing format: per-verse heading, main text, boxed notes inline.

**Required identity:** Both views present **identical text** — same translation, same additions, same italics, same quotation marks, same formulas. Notes content is identical across views; only placement differs (inline in Study; collected below in Reading layouts).

**Not a new edition:** Presentation layers are views of a single edition (Transparent *or* Reader), not a third edition type. Do not drift translation choices between the two views — that is prohibited by Rule 1 and Rule 24.

**File structure:** The Continuous Reading section appears **after** the Reading Guide and **before** the Verse-by-Verse Study section within the single chapter file. No new files are created.

### **VI. CANONICAL & OPERATIONAL RULES (added v2.4)**

#### **Rule 25: Divine Name (Tetragrammaton) Policy**
The Tetragrammaton (יהוה, YHWH) is the most contested rendering decision in Hebrew Bible translation. It must be addressed by explicit policy before any text containing it is translated (Genesis 2:4 onward).

**Permitted Renderings (choose one per edition, declare in front matter):**

| Option | EN | PT | DE | Notes |
|--------|-----|-----|-----|-------|
| **A. Consonantal** | YHWH | YHWH | JHWH | Maximum transparency; reflects unvocalized text. Recommended **default for Transparent Edition.** |
| **B. Vocalized scholarly** | Yahweh | Javé | Jahwe | Reconstructed vocalization; scholarly convention. Note that this is reconstruction, not Masoretic. |
| **C. Substitution (traditional)** | the LORD | o SENHOR | der HERR | Reflects Jewish *qere* tradition (read *Adonai*). Recommended **only for Reader Edition** with explicit declaration. |
| **D. Adonai transliteration** | Adonai | Adonai | Adonai | Honors Jewish reading tradition without English/PT/DE substitution. |

**Required Behaviors:**
- Edition front matter MUST state which option is in use.
- The choice is **locked per edition** for the entire translation; switching mid-project requires an editorial-log entry and re-alignment review across all completed verses.
- First occurrence in any book gets a 🔴 CRITICAL note explaining the choice and naming the alternatives not taken.
- **Never silently substitute.** "LORD" / "SENHOR" / "HERR" without declaration violates Rules 3, 11, and 22 simultaneously.
- When the text contains *Adonai YHWH* (אֲדֹנָי יהוה), distinguish in main text or note — do not collapse to "Lord GOD."
- *Elohim* (Rule 1, glossary) and *YHWH* are distinct lexemes; never merge.

**Why:** Of all possible silent theological imports, this is the largest. The ruleset cannot remain credible without an explicit policy.

#### **Rule 26: Textual Tradition — Qere/Ketiv, Vocalization, Variants**
The Masoretic Text is itself a layered tradition. The translator must declare which layer is being rendered.

**Three layers, with policy:**

**A. Consonantal text (ketiv):**
- Authoritative base layer.
- Where *ketiv* and *qere* diverge meaningfully, translate the **ketiv** in main text and note the **qere**.
- Exception: where *ketiv* is grammatically impossible or scribal-error consensus exists, follow *qere* and note the *ketiv* in Tier 2.

**B. Tiberian vocalization (Masoretic pointing, ~10th c. CE):**
- Treated as **the primary received reading tradition**, not as part of the consonantal text.
- Where vocalization forces a contested interpretive choice, note the alternative vocalization possibility in Tier 2 with an uncertainty level (Rule 13).

**C. Cantillation (te'amim):**
- Used to inform syntactic parsing (especially *athnach*, *zaqef*, *silluq* as clause-boundary markers).
- Where cantillation suggests a parsing different from common modern translations, follow cantillation in main text and note the alternative.

**D. Versional variants (LXX, Samaritan Pentateuch, DSS, Targumim, Peshitta, Vulgate):**
- Per Rule 22: noted, never silently adopted.
- Significant variants get a Tier 2 or Tier 3 note with siglum (𝔊, 𝔐, 𝔖𝔓, 4QGen-Exod^a, etc.) and BHS/BHQ apparatus reference.

**Citation format for source text:**
- BHS: `BHS, 5th rev. ed. (Stuttgart: Deutsche Bibelgesellschaft, 1997), p. <n>.`
- BHQ: `BHQ, fascicle <name>, ed. <name> (DBG, <year>), p. <n>.`
- Apparatus citations follow the apparatus's own siglum conventions.

#### **Rule 27: Inclusive & Gendered Language**
Hebrew has grammatical gender; English/Portuguese/German handle it differently. The translator must distinguish **grammatical gender** from **referential gender** from **interpretive gendering**.

**Core principles:**

**A. Generic *adam*:**
- Default rendering: "human / humano / Mensch" (per glossary).
- "Man / homem / Mann" only when the text contrasts with אִשָּׁה (*ishah*) and the contrast is referentially male.
- Plural / collective senses: "humans / humanidade / Menschen" — never "mankind / a humanidade dos homens / die Menschheit der Männer."

**B. *ish* and *ishah*:**
- Gendered pair, render as gendered pair: "man / woman," "homem / mulher," "Mann / Frau."
- Where *ish* appears alone with non-gendered force ("each one," "anyone"), translate non-gendered.

**C. *zakhar u-neqevah* (Gen 1:27):**
- Render directly: "male and female / macho e fêmea / männlich und weiblich."
- Avoid "man and woman" here — Hebrew uses biological-pair terms, not the social terms *ish/ishah*. Note the lexical distinction.

**D. Grammatical-gender mismatches (cross-language):**
- Per Rule 16/17: tracked in editorial log.
- A note is required only when the mismatch is **theologically or referentially loaded** (e.g., *ruach* → German masculine *Geist*).

**E. Pronouns for the divine:**
- Hebrew uses masculine grammatical forms for *Elohim/YHWH*. This is grammatical, not ontological.
- All three editions: retain masculine pronouns where Hebrew grammar forces them; do **not** substitute gender-neutral renderings unsupported by the text.
- A one-time note may flag this as a grammatical, not metaphysical, feature.

**Why:** Translation in 2026 cannot remain silent on this. The rule does not legislate a particular ideology — it requires *visible disciplined treatment* consistent with the Prime Directive.

**F. Collective singulars and pronoun agreement (added v2.4.2):**

Hebrew collective singular nouns (e.g., **זֶרַע** *zera* = "seed/offspring") take grammatically singular pronouns (הוּא *hu* = "he/it") while potentially referring to a group. English forces a choice that Hebrew does not:

- **"he"** — follows Hebrew masculine singular grammar but imports individuation (one male person)
- **"it"** — dehumanizes offspring
- **"they"** — breaks singular agreement

**Policy:**
- Follow Hebrew grammatical agreement in the main text (masculine singular → "he" in English).
- The note **must** flag the collective scope of the noun: *"zera is collective singular — 'he' follows Hebrew masculine agreement but the referent may be one or many descendants."*
- Do **not** capitalize "He" to import Christological individuation (Rule 3).
- Do **not** switch to "they" to import modern inclusive grammar unsupported by the Hebrew form.
- The tension is acknowledged, not resolved. This is honesty.

#### **Rule 28: Review & Sign-off Workflow**
No verse ships without documented review. Rules cannot substitute for qualified human review.

**Required reviewer roles per verse:**

| Role | Qualification | Responsibility |
|------|---------------|----------------|
| **Hebraist** | Reading proficiency in Biblical Hebrew; access to BHS/BHQ apparatus | Verifies main-text faithfulness to Hebrew; signs off on glossary application and ambiguity preservation |
| **Target-language editor** (one per language: EN, PT, DE) | Native or near-native; familiarity with target literary register | Verifies Rule 10 register, Rule 11 addition marking, Rule 18 number forms, idiomatic correctness |
| **Cross-alignment reviewer** | Reads all three target languages | Runs Rule 16 checklist; signs off on EN ↔ PT ↔ DE consistency |
| **Project lead** | Final accountability | Resolves disagreements; authorizes editorial-log exceptions |

**Workflow per verse:**
1. Drafter produces verse + notes in all three languages following the 24+ rules.
2. Hebraist reviews against Hebrew; flags or approves.
3. Target-language editors review their language; flag or approve.
4. Cross-alignment reviewer runs Rule 16 checklist.
5. Disagreements escalate to project lead; resolution recorded in editorial log.
6. Verse marked `signed-off` only when all four reviewer roles approve (or lead overrides with logged justification).

**For AI-assisted drafting (current project condition):**
- Each AI-assisted verse must record: model identifier, model version, date, prompt summary or hash, and human-reviewer accept/edit/reject decision.
- AI cannot occupy a reviewer role. AI output is a draft, not a sign-off.
- The provenance record lives in the editorial log per verse.

**Until reviewer roles are filled:** verses may be drafted but must be marked `provisional — pending review` in the front matter of the published file.

#### **Rule 29: Contextual and Comparative Study Material (added v2.5)**

Contextual enrichment (ancient parallels, archaeology, science, reception history, linguistics, curiosities) may be included **only** in Tier 3 companion files or clearly separate resources. Never in Tier 1. Only minimally in Tier 2 (as cross-references governed by Rule 14).

**Location:** Companion files at `{locale}/{book}/study/CHAPTER-{N}-CONTEXT.md`, separate from the translation chapter files.

**Core constraint:** Enrichment presents what the text says, what other sources say, and what remains unknown — then stops. **The reader draws conclusions. The enrichment draws none.**

**Required behaviors:**
1. Never alter or redefine the main translation
2. Never treat contextual material as if it were part of the Hebrew wording itself
3. Always label with **both** a claim-type tag and a confidence level (see labeling system below)
4. Distinguish textual observation from interpretation
5. Distinguish historical or scientific comparison from textual meaning
6. Avoid concordism ("Genesis secretly taught modern science") and reverse-concordism ("modern science shows Genesis is wrong") equally — per Rule 3 corollary
7. Avoid confessional harmonization — per No-Harmonization Principle (Rule 22)
8. Remain subordinate to the translation rather than controlling it
9. Cite sources for every non-textual claim (Sources section mandatory per companion file)
10. Reader Edition must not become a smuggling channel for contextual material into the reading flow

**Dual-Label System (integrates with Rule 13):**

Every contextual claim carries two labels:

*Claim-type tag (what kind of claim):*

| Tag | Meaning |
|-----|---------|
| TEXTUAL | Derived directly from the Hebrew text |
| STRONG INFERENCE | Logically entailed by the text, not stated explicitly |
| POSSIBLE INFERENCE | One legitimate reading among others |
| COMPARATIVE PARALLEL | Attested in another ANE or ancient source |
| LATER RECEPTION | Post-biblical Jewish, Christian, Islamic, or philosophical reading |
| HISTORICAL / ARCHAEOLOGICAL | Based on material or historical evidence |
| SCIENTIFIC COMPARISON | Modern empirical observation compared to text |
| SPECULATION | No strong textual or evidential basis |

*Confidence level (how sure — per Rule 13):*

| Level | Use |
|-------|-----|
| VERIFIED / PROBABLE | Strong evidence, wide agreement |
| POSSIBLE | Reasonable, debated |
| UNCERTAIN | Genuinely unclear |
| SPECULATIVE | Must be rare and clearly flagged |

*Combined label format:*
```
[COMPARATIVE PARALLEL — VERIFIED]
Enuma Elish also presents primordial waters divided to form sky and earth.
Source: ANET, Pritchard 1969, pp. 60-72.
```

**Companion file standard sections (A–H) — AVAILABLE, NOT ALL MANDATORY:**

The following sections define the **menu** of what a companion file may contain. **Include a section only when there is substantive, sourced content for it.** An empty or thin section is worse than an absent one. Not every chapter will have material for every section — Genesis 1 has rich ANE parallels; a genealogy chapter may have none. Forcing 8 sections on every chapter produces the kind of padding the project rejects.

**Only Section H (Sources) is mandatory** for every companion file — if you have no sources, you have no enrichment.

- **A. Hebrew Text Features Exposed by TT** — purely textual observations the TT makes visible. Include when the TT's transparency reveals features traditional translations smooth over.
- **B. Ancient Near Eastern (ANE) Parallels** — texts from neighboring ancient cultures (Mesopotamia, Egypt, Ugarit, Canaan) that share motifs, vocabulary, or structural patterns with the chapter. Framed as parallels and contrasts, not as dependence. Include when attested parallels exist.
- **C. Historical and Archaeological Context** — ancient setting, material culture, dating debates. Include when archaeological evidence illuminates the chapter.
- **D. Linguistic and Philological Deep Dives** — comparative Semitics, rare words, semantic fields, syntax studies beyond Tier 2 note space. Include when the chapter contains linguistically complex or debated terms.
- **E. Scientific Correspondence and Non-Correspondence** — comparison between what the text presents and what modern science describes. Neither concordism nor anti-concordism. Include only when the comparison is genuinely illuminating, not as a reflex.
- **F. Later Reception in Other Traditions** — Rabbinic, Patristic, Islamic, philosophical readings. Clearly labeled as post-biblical reception. Include when the chapter has generated significant interpretive traditions.
- **G. Curiosities and Open Questions** — text-linked, tightly curated observations. Include when the chapter has genuinely striking features worth noting. No trivia pile.
- **H. Sources Consulted** — **MANDATORY for every companion file.** No unsourced claims ship.

**Mandatory disclaimer at top of every companion file:**
> This companion file provides contextual and comparative study material. It does not redefine, expand, or control the main translation. Parallels do not prove dependence. Modern models do not define ancient intent. All entries are labeled by type and certainty and must be read as background, not as translation.

**Trilingual implementation:** EN-first pilot; PT-BR and DE after EN pilot is reviewed and stable. Rule 16 (cross-language alignment) applies to companion files once multilingual versions exist.

**Editorial log:** Every contextual entry records claim-type, confidence level, source basis, and AI/human provenance in the editorial log.

**Discipline-specific material and section discovery:**

Sections A–G are organized by **claim type** (what kind of knowledge claim), not by academic discipline. Do not create dedicated sections for individual disciplines (Archaeology, Paleontology, Geology, Anthropology, Oceanography, Cartography, Philosophy, Astronomy, Biology, etc.). Instead, discipline-specific material goes as **sub-headings within the appropriate claim-type section**, identified by the source citation:

```markdown
## E. Scientific Correspondence and Non-Correspondence

### Geology — single landmass question
**[SCIENTIFIC COMPARISON — POSSIBLE]**
The text presents singular *eretz* (land)...
Source: [Smith, Journal of Geology, 2020]

### Oceanography — waters above and below
**[SCIENTIFIC COMPARISON — TEXTUAL observation]**
The raqia separates waters...
Source: [Jones, Marine Science Review, 2018]
```

The discipline is visible through the sub-heading and source citation. No dedicated empty section needed.

**Process for discovering what sections a chapter needs (text-driven, not discipline-driven):**

1. Read the chapter's TT translation + Tier 2 notes
2. Ask: *"What does this text make visible that a reader would want context for?"*
3. For each observation, classify by claim-type (which of A–G?) and find relevant sourced material
4. If a discipline has substantive content for this chapter, it appears as entries or sub-headings. If not, it doesn't.
5. Never pre-declare empty disciplinary sections. The text drives the structure; the structure does not drive the text.

This keeps companion files lean and text-relevant regardless of how many academic disciplines *could theoretically* apply.

## AMENDMENT & LOCK PROTOCOL (added v2.4)

"LOCKED" means: **no rule changes mid-translation-cycle without protocol.** It does not mean "frozen forever."

### **Translation cycle**
A translation cycle = the work from version-tag to version-tag (e.g., v2.3 → v2.4). Within a cycle, the ruleset is immutable.

### **Re-opening a locked rule**
1. **Proposal:** Written proposal in `docs/rules/proposals/`, naming the rule, the change, and the justification.
2. **Impact assessment:** Project lead (or designated reviewer) lists every signed-off verse affected by the change.
3. **Decision window:** Minimum 14 days for reviewer comment.
4. **Resolution:** Accept → version bump (vX.Y → vX.Y+1) and amendment recorded in Version History; Reject → proposal archived with reasoning; Defer → next cycle.
5. **Affected verses:** Re-reviewed under the new rule; status reverts to `provisional` until re-signed-off.

### **Emergency amendment**
Bug fixes (factual errors, contradictions between rules, broken examples) may be patched within a cycle as **point releases** (vX.Y.Z), without the full proposal cycle, but must still be logged in Version History and announced to all reviewers.

### **What "LOCKED" forbids during a cycle**
- Silent edits to glossary defaults.
- Silent edits to formulas (Rule 7) or edition policies (Rule 24).
- Adding or removing rules without version bump.

## GERMAN PRE-TRANSLATION REQUIREMENT

**Before beginning German translation, the following decision must be documented:**

### **Luther Bible Relationship Policy**

This decision affects editorial framing and marketing positioning, **NOT** core translation methodology. The German TT is built from Hebrew using TT rules regardless of Luther stance.

**Background:**
The Luther Bible (1545/1984/2017) has enormous cultural weight in German-speaking contexts. Any new German Bible translation operates in its shadow. This project must decide how to position itself relative to that tradition.

**Three Options:**

**A. Complete Independence**
- Build from Hebrew using TT rules; Luther irrelevant to methodology
- No comparative notes to Luther Bible in public materials
- May naturally converge with Luther when both accurately render Hebrew
- Divergences are coincidental, not polemical
- **Marketing framing:** Independent scholarly translation for 21st century
- **Advantage:** Clean break; no baggage
- **Risk:** May feel "foreign" to readers expecting Luther resonance

**B. Selective Acknowledgment**
- Note convergences/divergences in supplementary materials (appendix or study edition)
- Acknowledge Luther's influence on German Bible tradition
- Document where Luther made interpretive choices vs. linguistic choices
- Show where TT transparency reveals features Luther smoothed
- **Marketing framing:** Transparent alternative within tradition
- **Advantage:** Contextualizes work for German readers
- **Risk:** Requires careful Luther scholarship

**C. Explicit Alternative**
- Position as transparency counter to Luther's choices
- Highlight where Luther smoothed, theologized, or interpreted
- Use Luther as teaching contrast in appendix
- Show "here's what Luther did; here's what Hebrew actually says"
- **Marketing framing:** Post-Luther reformation of transparency
- **Advantage:** Clear pedagogical value
- **Risk:** Could appear polemical; requires nuanced handling

**Decision Affects:**
- Introductory framing language in German edition preface
- Comparative notes in supplementary materials (if any)
- Marketing positioning to German-speaking audiences
- Potential academic reception

**Decision Does NOT Affect:**
- Core translation from Hebrew (built on TT rules, not Luther)
- Application of 24 TT rules (language-neutral principles)
- German grammatical policies (capitalization, gender, articles, Konjunktiv)
- Locked glossary construction (built from Hebrew, not German tradition)
- Translation mechanics (same system as English/Portuguese)

**REQUIREMENT:** 
- Document chosen option (A, B, or C) before starting Genesis 1 in German
- Record decision in editorial log with justification
- Apply consistently across German translation project
- This decision is **editorial framing, not methodology**
- If needed, option can include hybrid elements (e.g., B with elements of C)

**NOTE:** The German TT is **always** built from Hebrew using TT principles. The Luther policy only determines how we **talk about** the translation to German-speaking audiences, not how we **create** it.

## LANGUAGE-SPECIFIC ADVANTAGES

### **English:**

**Useful Tools:**
- "Shall be" for jussive (formal but effective)
- Slight awkwardness acceptable when mirroring Hebrew
- Word order more flexible than assumed

**Accept Limitations:**
- Lost grammatical gender (note when theologically significant)
- Must add articles frequently (mark additions per Rule 11)
- Limited verb conjugation (can't show all Hebrew nuances)
- No subjunctive mood for jussive (must use workarounds)

---

### **Brazilian Portuguese (Natural Advantages):**

**Exploit These Strengths:**
- ✓✓ **Subjunctive mood** = perfect for Hebrew jussive ("Haja luz")
- ✓✓ **Grammatical gender** = preserves Hebrew gender naturally
- ✓✓ **Pronoun dropping** = matches Hebrew ("E Deus viu que bom" - no subject pronoun needed)
- ✓✓ **Gerund** = excellent for Hebrew participles ("pairando")
- ✓✓ **Flexible word order** = closer to Hebrew than English
- ✓✓ **Compression** = can often match Hebrew compression without additions

**Watch Out:**
- Resist archaic "Bible Portuguese" 
- ✗ "E disse o Senhor Deus..." (when Hebrew lacks "the Lord")
- ✓ "E Deus disse..." (elevated but contemporary)
- Don't over-import Portuguese Catholic/Protestant Bible tradition vocabulary

**Why Portuguese Excels for TT:**
Portuguese may be the **strongest of the three languages** for this project because:
1. Subjunctive naturally handles jussive
2. Grammatical gender preserves Hebrew distinctions
3. Compression matches Hebrew better than English or German
4. Fewer grammatical additions needed (cleaner Tier 1)

---

### **German (Natural Advantages):**

**Exploit These Strengths:**
- ✓✓ **Konjunktiv (subjunctive)** = can match Hebrew jussive mood ("Es werde Licht" - Konjunktiv I)
- ✓✓ **Compound words** = excellent for Hebrew construct chains and poetic doubling
- ✓✓ **Flexible word order** = closer to Hebrew than English (V2 word order allows fronting)
- ✓✓ **Grammatical gender** = can preserve Hebrew gender distinctions (when they match)
- ✓✓ **Article system** = rich enough to track Hebrew ה (definite article) distinctions
- ✓✓ **Passive voice** = robust system with werden + past participle matches Hebrew passive well
- ✓✓ **Participle system** = excellent present and past participles for Hebrew aspectual distinctions
- ✓✓ **Case system** = can show grammatical relationships Hebrew shows through word order

**Watch Out:**
- **Gender mismatches:** רוּחַ (fem.) → Wind/Geist (masc.); אֶרֶץ (fem.) → Land (neut.); note when theologically relevant
- **Luther Bible echo:** Avoid sounding like translation of translation; build directly from Hebrew
- **Over-compounding:** German can create elaborate compounds not justified by Hebrew (e.g., "Himmelsgewölbekonstruktion" for raqia)
- **Capitalization:** All nouns capitalized grammatically—this is NOT theological emphasis (note when needed)
- **Article gender:** Must choose der/die/das; when Hebrew gender differs from German, track in log

**Critical Decisions for German:**
1. **Konjunktiv I vs. modern constructions for jussive** - edition-dependent (Transparent: Konjunktiv I; Reader: modern)
2. **Luther relationship policy** - pre-translation requirement (Options A/B/C above)
3. **Compound usage balance** - natural constructs OK, over-precision forbidden
4. **Gender mismatch handling** - always note when theologically relevant; track all in log

**German Compound Examples:**
```
✓ Acceptable: "Meeresbewohner" (sea-dwellers) for construct chain
✓ Acceptable: "samend Samen" (seeding seed) for root doubling
✗ Too much: "Himmelsgewölbekonstruktion" (sky-vault-construction) for raqia
✗ Too much: "Urschöpfungschaoszustand" (primal-creation-chaos-state) for tohu vavohu
```

**Why German Has Unique Challenges:**
German is culturally embedded in Luther Bible tradition in ways English/Portuguese are not. Any German Bible translation must navigate this reality. However, **methodologically**, German is strong for TT because of Konjunktiv, compounds, and grammatical precision.
