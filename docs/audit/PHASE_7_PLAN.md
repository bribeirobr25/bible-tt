## 1. Goal (one sentence)

Every technical term — Greek-grammar, manuscript-tradition, scholarly-method — that appears in a John or Matthew companion / introduction file is **glossed inline at first use per file** so a non-specialist reader can follow the entry without leaving the page.

The standard is the "grandmother test" from `docs/feedback/DEFERRED_TASKS.md` Task 2: a literate non-specialist reading end-to-end should never hit a term they cannot decode from context. Manual review per Rule 28 §line-899 (no automated check exists; the test is subjective).

## 2. Why this is not just a find-replace

Three real decisions sit underneath:

1. **Term inventory is unbounded.** The original audit named three (`Colwell`, `predicate nominative`, `anarthrous`). The 2026-05-09 inventory below shows ~20 high-frequency technical terms across the 30 target files — not just three.
2. **Cross-locale gloss consistency.** The same term must map to a single PT-BR / DE / ES gloss applied everywhere. Without a per-term decision, two locale editors produce two phrasings.
3. **"First use per file" boundary.** The per-section variant (gloss every H2 / H3 reset) bloats files; the per-file variant (one gloss per file) is the simplest defensible rule for our scale and matches the existing Genesis precedent.

These decisions belong upstream of the editing pass. This plan pins them.

## 5. Section-boundary rule

**Decision: gloss on first occurrence per file** (not per H2 / H3 / per-section). Reasoning:

1. **Reader experience:** a typical reader opens a chapter companion top-to-bottom; the first-occurrence-glossed term gives them what they need for the entire file.
2. **Maintenance:** per-file rule reduces the gloss count by ~3–5× compared to per-section, which keeps file size manageable and edits localized.
3. **Existing Genesis precedent:** `content/en/genesis/INTRODUCTION.md` glosses Masoretic Text on first mention (line 175), Septuagint and JEDP each once, then proceeds without re-glossing. This is the working convention — Phase 7 propagates it.

Cross-file linking handles the deep dives — once a term is glossed plus has a `§N` pointer in another file, subsequent files can use the term naked because the pointer is one click away.

**Edge case:** book introductions and chapter-1 companions that introduce a term should carry the FULL gloss. Chapters 2 and 3 of the same book may rely on the chapter-1 file's gloss via "see CHAPTER-1-CONTEXT §X" cross-reference.

### Definitional clarity: "glossed vs naked" (audit §4.2)

When a term is **explained in surrounding prose at first use** (e.g., John 1 CONTEXT §A4: *"The verb ἐγένετο (egeneto) is in the aorist tense, which in Greek views an event as a single completed action, a one-time entry into a new state."*), **no parenthetical gloss is added**. The parenthetical-format gloss in §4 is a fallback for terms used without surrounding explanation, NOT a redundant marker on top of existing prose.

The judgment criterion is the **grandmother test**: can a non-specialist reader understand the term from what's already on the page? If yes — naked usage is fine, no gloss needed. If no — add the §4 parenthetical gloss at first use.

This means file passes will face per-term judgment calls; locale editors should err toward the permissive reading (existing prose counts as glossed) and add parenthetical glosses only where the prose genuinely doesn't explain the term.

### Floor not ceiling for existing glosses (audit §5.1)

The §4 gloss table represents a **floor, not a ceiling**. Where existing inline glosses in the same locale are richer or more contextually appropriate than the table's gloss, the existing glosses are preferred — Phase 7 specifies what to add when no gloss exists, not what to overwrite. Examples already in the codebase: PEOPLE.md Yosef-entry's *tektōn* gloss is richer than §4's; PEOPLE.md Yosef-entry's *dikaios* gloss carries the moral-rank distinction that §4's table omits. Both are kept as-is; the §4 gloss is added elsewhere only.

### Existing in-context discussions are kept (audit §5.2)

Phase 7 **adds** glosses where missing; it does **not remove** existing in-context discussions. John 1 CONTEXT §A8 has Colwell explained richly with E.C. Colwell *JBL* 52, 1933 citation — that deeper discussion stays even if §A3's brief gloss handles "first use." The per-file rule is about adding glosses where missing, not pruning existing redundancy.

### Per-section switch trade-off (audit §5.3)

If the 7.1 canary suggests per-file feels too sparse and a switch to per-section is considered: **note that switching would also imply a per-section pass on Genesis files for cross-book consistency** — not just additional work on John/Matthew. Re-estimate total effort under that scenario to include Genesis (12 chapter companions × 4 locales = 48 additional files, currently per-file-glossed only, would need per-section passes). The "lose a couple of hours" framing in Risk #4 understates the cost — likely a full additional sub-phase.
